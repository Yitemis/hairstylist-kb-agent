## 0. 文档说明

本文档为个人技术项目的产品需求文档，用于规划一个**基于 AgentScope 框架**、面向**美发行业 B 端**的智能知识助手应用。

> **合规声明**：本项目所有代码基于开源框架 AgentScope（Apache-2.0）从零实现，借鉴行业通用的 RAG 工程理念，不包含任何第三方商业项目的源代码或私有实现。测试数据来源于公开资料，仅用于技术演示。

---

## 1. 项目背景

### 1.1 行业现状
美发行业是典型的**知识密集型 + 人员流动性高**的服务业：
- 产品线庞杂（洗护、染烫、造型等数百 SKU），成分与适用发质各异；
- 技术门槛高（染烫配方、调色比例、操作流程 SOP）；
- 新人培养周期长，老员工经验难以沉淀和复用；
- 服务话术、门店制度等知识分散在各类文档中，查找低效。

### 1.2 核心痛点
| 角色 | 痛点 |
|------|------|
| 新入职发型师 | 记不住海量产品成分/适用发质；不熟悉染烫配方与流程 |
| 门店员工 | 顾客提问时无法快速给出专业、一致的回答 |
| 门店/品牌 | 知识散落在 PDF/Word/图片/表格中，检索慢，培训成本高 |

### 1.3 解决方案
构建一个**企业内部的智能知识助手 Agent**：员工用自然语言提问，助手自主检索企业知识库，结合检索到的专业资料给出准确、可溯源的回答，并支持多轮追问。

---

## 2. 产品定位

- **产品形态**：形态 A —— 面向发型师/门店员工的专业知识助手（toB）
- **服务对象**：发型师、门店员工（企业内部用户）
- **一句话定位**：让每一位发型师，都拥有一个"随身的资深技术总监 + 产品专家"。
- **演进路线**：先做深 toB 知识助手 → 后续可横向扩展为 toC 顾客顾问、门店运营助手（本 PRD 只聚焦 toB 第一阶段）。

## 3. 目标用户与使用场景

### 3.1 三大核心场景（按优先级分层）

| 优先级 | 场景 | 说明 | 数据特征 | 技术看点 |
|:---:|------|------|---------|---------|
| **P0** | A. 产品知识查询 | "这款洗发水适合什么发质？主要成分？和另一款的区别？" | 表格/结构化多 | 表格解析、父子分块 |
| **P0** | B. 技术配方查询 | "漂发后染亚麻灰，调色比例？流程注意事项？" | 步骤 + 比例表 | 结构化召回、精排 |
| **P1** | C. 话术/SOP 查询 | "顾客说染完褪色快怎么回应？烫发标准流程？" | 纯文本为主 | 语义检索 |

> **优先级设计说明**：P0 场景数据结构化程度高（表格、配方），是 RAG 检索质量优化（父子分块、Rerank、表格深加工）的主战场，技术价值最高；P1 场景以纯文本为主，实现简单，用于丰富知识库覆盖面。

### 3.2 典型用户旅程（以场景 A 为例）
1. 发型师在 Web 界面输入："油性发质、有头皮屑，推荐哪款洗发水？主要看什么成分？"
2. 助手自主判断需要检索知识库，检索"油性发质 洗发水 去屑 成分"相关内容；
3. 检索结果经 Rerank 精排后，助手结合父块完整上下文生成专业回答；
4. 回答中标注引用来源（哪份产品手册），支持发型师追问："那这款和 XX 款有什么区别？"
5. 助手基于多轮上下文继续检索并对比回答。

## 4. 功能需求

### 4.1 MVP 阶段（P0，先做）

| 编号 | 功能 | 描述 |
|------|------|------|
| F1 | 多格式文档解析入库 | 支持 PDF / Word / 图片 / 表格等格式解析，构建知识库 |
| F2 | 智能问答（Agentic RAG） | Agent 自主决策是否检索、检索什么，结合结果专业回答 |
| F3 | 多轮对话 | 支持上下文追问、澄清、对比 |
| F4 | 答案溯源 | 回答标注引用来源（来自哪个文档/片段） |
| F5 | 流式输出 | Web 界面打字机式实时输出（基于框架事件流） |

### 4.2 进阶阶段（P1/P2，扩展功能）

| 编号 | 功能 | 描述 |
|------|------|------|
| F6 | 主动推荐 | "顾客发质细软想蓬松，推荐哪些产品+方案"——组合多条知识推理 |
| F7 | 话术/SOP 覆盖 | 扩展场景 C 知识 |
| F8 | 小程序端 | 从 Web 扩展到微信小程序（移动端便携查询） |

## 5. 技术架构

### 5.1 总体架构

```
┌─────────────────────────────────────────────┐
│                 前端（Web，后续小程序）          │
│         流式对话界面（打字机效果）               │
└───────────────────┬─────────────────────────┘
                    │ 事件流 (SSE / AgentEvent)
┌───────────────────▼─────────────────────────┐
│              AgentScope Agent（推理核心）        │
│   ReAct 循环：自主决策何时检索、如何回答            │
│                                               │
│   ┌─────────────────────────────────────┐     │
│   │      RAGMiddleware（agentic 模式）      │     │
│   │   Agent 自主调用 search_knowledge 工具  │     │
│   └──────────────────┬──────────────────┘     │
└──────────────────────┼────────────────────────┘
                      │
      ┌───────────────▼────────────────┐
      │      自定义 KnowledgeBase        │
      │  （检索 + 父块召回 + Rerank 精排）  │
      └───┬──────────┬──────────┬───────┘
          │          │          │
   ┌──────▼───┐ ┌────▼─────┐ ┌──▼──────┐
   │ Embedding │ │  向量库    │ │ Rerank  │
   │  模型      │ │(子块向量)  │ │  模型    │
   └───────────┘ └───────────┘ └─────────┘

      ┌─────────────────────────────────┐
      │       离线索引流水线（灌数据）        │
      │  Parser → 父子分块 → Embed → 入库    │
      │  （多格式解析 + 表格深加工）           │
      └─────────────────────────────────┘
```

### 5.2 关键技术设计

| 技术点 | 说明 | 实现方式 |
|------|------|---------|
| **父子分块** | 用小块做向量检索、用大块提供上下文 | 继承框架 `ChunkerBase` 自定义实现 |
| **两阶段检索** | 向量检索粗筛 + Rerank 精排 | 自定义 `KnowledgeBase` 增加 rerank 层 |
| **多格式解析** | 表格转结构化文本 | 继承框架 `ParserBase` 自定义实现 |
| **Agentic RAG** | Agent 自主决策检索 | 框架 `RAGMiddleware(mode="agentic")` |
| **流式输出** | 事件驱动的实时输出 | 框架 `reply_stream` 事件系统 |
| **模型可插拔** | 多厂商可切换 | 基于框架 `ChatModelBase` 抽象接入 |

### 5.3 技术选型

| 层次 | 选型 | 状态 |
|------|------|------|
| Agent 框架 | AgentScope 2.0（本地可编辑安装） | 已定 |
| Chat 模型 | 火山方舟（OpenAI 兼容接入 / 自定义适配器） | 待确认具体型号 |
| Embedding 模型 | 火山方舟 Embedding | 待确认型号 |
| Rerank 模型 | 待定（火山方舟 / 开源 bge-reranker / 其他） | 待确认 |
| 向量库 | 入门 Qdrant(内存) → 生产 Milvus | 待定 |
| 后端 Web | FastAPI（框架 service 生态） | 建议 |
| 前端 | 简单 Web UI（流式） → 微信小程序 | 建议 |

> **模型可插拔设计**：Chat/Embedding/Rerank 三类模型均通过统一抽象接入，具体厂商与型号由配置决定。火山方舟型号确认前不阻塞开发，确认后仅需修改配置。

## 6. RAG 数据流详解

### 6.1 离线索引（灌数据）
```
原始文件（PDF/Word/图片/表格）
  → Parser 解析（表格深加工为结构化知识单元）
  → 父子分块（父块=完整语义段，子块=细粒度检索单元）
  → 子块 Embedding 向量化
  → 子块向量入向量库，父块原文入存储层（关联 ID）
```

### 6.2 在线检索（回答问题）
```
用户提问
  → Agent 判断需检索，生成查询
  → 查询向量化 → 向量库召回 Top-N 子块（粗筛）
  → Rerank 模型精排 → Top-K
  → 由命中子块回溯其父块完整原文
  → 父块内容 + 引用来源 注入 Agent 上下文
  → Agent 生成专业、可溯源的回答
```

## 7. 里程碑规划

| 阶段 | 目标 | 交付物 |
|------|------|--------|
| **M0 环境搭建** | 项目骨架 + 框架安装 + Hello World Agent | 可运行的最简 Agent |
| **M1 RAG 打通** | 用框架自带组件跑通完整 RAG 链路 | 命令行可检索问答 |
| **M2 父子分块** | 自定义 ChunkerBase 实现父子分块 | 父子召回生效 |
| **M3 Rerank 精排** | 自定义 KnowledgeBase 加 rerank | 检索质量提升（可量化对比） |
| **M4 多格式解析** | 自定义 Parser 支持真实资料格式 + 表格深加工 | 真实美发资料入库 |
| **M5 Agent 集成** | RAGMiddleware agentic 模式接入 | 完整问答 Agent |
| **M6 Web 界面** | 流式对话 Web UI | 可演示的产品 |
| **M7 进阶扩展** | 主动推荐 / 话术SOP / 小程序 | 可选扩展功能 |

## 8. 评估指标

- **检索准确率**：对比「仅向量检索」与「向量 + Rerank」的命中率（用一批测试问答对量化）
- **回答完整性**：对比「扁平分块」与「父子分块」的回答质量
- **响应体验**：首字延迟（流式输出）
- **知识覆盖**：支持的文档格式数、入库文档量
